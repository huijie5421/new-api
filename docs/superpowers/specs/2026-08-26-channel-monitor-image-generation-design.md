# V1 独立渠道监控：生图模型检测设计

## 目标

在 V1 渠道监控页面的“独立监控任务”中增加 OpenAI 兼容的生图检测模式，使用 `POST /v1/images/generations` 对指定渠道模型进行低成本测活。现有聊天、Responses、Anthropic、Gemini、Grok 文本模式保持兼容，不改变已有任务的数据和调度行为。

## 已确认的行为

- 生图检测是 V1 独立监控任务的一种明确 API 模式，不根据模型名称猜测。
- 生图模式的成功响应按耗时显示：耗时小于 60 秒为绿色，耗时大于或等于 60 秒为黄色；失败始终为红色。文本模式继续保持原有成功绿色、失败红色规则。
- 只有以下情况显示红色：HTTP 非 2xx、网络错误、超时、JSON 无法解析、响应 `data` 为空，或首个结果既没有非空 `url` 也没有非空 `b64_json`。
- 文本任务继续使用现有默认间隔 60 秒、默认超时 10 秒和超时上限 60 秒。生图任务新建时默认间隔 300 秒、默认超时 90 秒，超时可在 1–180 秒内调整且必须小于间隔；超时本身属于失败。
- 监控间隔仍由任务级别配置（沿用现有 60–3600 秒范围），不会写死轮询频率。
- 生图模式仅出现在支持 OpenAI 兼容 Bearer 认证的 OpenAI、Grok 提供商中；Anthropic/Gemini 不展示该选项。

## 请求与模板

### URL 与认证

沿用现有 endpoint 规范化和 SSRF 防护。将配置的 endpoint 规范化到服务根地址后，请求：

```
POST {endpoint}/v1/images/generations
Authorization: Bearer {api_key}
Content-Type: application/json
```

若 endpoint 已包含 `/v1`，不得重复拼接；行为与现有 OpenAI Chat/Responses 适配器一致。

### 默认请求体

默认（auto/minimal）模板使用与默认渠道生图测试相同的最小语义：

```json
{
  "model": "MODEL_FROM_TASK",
  "prompt": "a cute cat",
  "n": 1,
  "size": "1024x1024"
}
```

高级 custom 模式允许管理员调整生图供应商支持的参数（例如 `size`、`quality`、`response_format`），但系统始终注入任务模型和健康检查 prompt，并将 `n` 限制为 1，避免一次检测产生多张图片和不可控费用。模板内容存储在现有渠道监控模板表中，无新增表。

### 响应校验

仅校验测活所需的响应契约，不下载图片本体：

1. HTTP 状态为 2xx；
2. body 可解析为 JSON；
3. `data` 为非空数组；
4. `data[0].url` 或 `data[0].b64_json` 至少一个为非空字符串。

满足条件即 `success`；否则记录可读错误原因并标记失败。这样避免监控任务额外消耗带宽，也不引入新的图片下载/SSRF 路径。

## 后端改动边界

1. 新增 `image_generation` API mode 常量、校验规则和默认模板种子（幂等）。
2. 新增 OpenAI Image provider adapter，复用现有 HTTP 客户端、endpoint 安全校验、鉴权头、重试和历史记录链路。
3. 扩展 body builder，使默认模板按 API mode 生成；文本模式输出保持原样。
4. 保持 `ChannelMonitor.APIMode` 字段及已有 API 响应兼容，不做数据库迁移。
5. 生图任务结果沿用现有历史、状态汇总和手动“立即检测”流程；不新增独立调度器。

## 前端改动边界

1. 独立监控任务表单和模板表单增加“生图生成”选项；仅 OpenAI/Grok 可选。
2. 生图模式显示可编辑的超时、间隔和高级请求体设置，并在表单中提示“成功且耗时小于 60 秒为绿色，达到 60 秒为黄色，失败为红色”。
3. 增加简体中文翻译；状态徽标仅对生图模式按上述耗时规则显示，文本模式不变。
4. 现有渠道列表、任务详情、历史记录和模板管理布局不改变。

## 错误与可观测性

- 错误信息沿用现有脱敏规则，不回显 API Key。
- 记录 HTTP 状态、耗时、截断后的供应商错误信息和失败阶段（请求/响应/契约）。
- 成功记录响应耗时；生图模式耗时小于 60 秒显示绿色，达到 60 秒显示黄色，文本模式保持现有成功绿色。
- 任务超时由任务级 timeout 控制；超时后立即结束并标红。

## 测试与验收

### 后端

- adapter 单元测试：URL 拼接（endpoint 含/不含 `/v1`）、Bearer 头、默认/自定义 body、`n` 限制。
- response validator 单元测试：合法 URL、合法 base64、空 data、缺少 url/base64、非 JSON、非 2xx。
- 配置校验测试：仅 OpenAI/Grok 接受 `image_generation`，timeout 范围和 interval 约束正确。
- 模板种子幂等测试，已有文本模板不被覆盖。

### 前端

- API mode 类型、表单可见性、提交 payload 和中文文案测试。
- 生图状态徽标测试：成功且耗时小于 60 秒为绿色，达到 60 秒为黄色，失败始终红色；文本模式成功仍为绿色。

### 验收场景

1. 创建 OpenAI 生图独立任务，填写模型和 API Key，手动检测返回有效 `data[0].url` 且耗时小于 60 秒，页面显示绿色。
2. 返回有效响应但耗时达到 60 秒，页面显示黄色。
3. 同一任务模拟超时、HTTP 401、空 `data`、仅错误 JSON，均显示红色并在详情展示原因。
4. 将生图 timeout 调整到 60/90/120 秒可保存并生效；间隔可独立调整且始终大于 timeout。
5. 旧的 Chat/Responses 任务升级后可正常检测，数据库无需重建。
6. Grok 生图兼容 endpoint 可按同一模式检测；Anthropic/Gemini 表单不出现该选项。

## 不在本次范围

- 不调用已有 controller 的“按渠道测试”接口，不把 channel_id 引入独立监控表。
- 不实现图片下载、像素质量评估、内容审核或 V2 监控任务。
- 不修改文本监控的颜色阈值和官方会话认证逻辑。
