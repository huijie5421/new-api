# 数据看板渠道筛选设计

日期：2026-08-27

## 目标

在管理员数据看板中增加渠道筛选，支持选择单个或多个渠道，使请求量、费用、Token、缓存读取量、缓存命中率、模型图表及流量图均只统计所选渠道。

## 范围与权限

- 仅管理员及以上角色展示并使用渠道筛选。
- 普通用户数据看板保持现状，不显示渠道选项，也不向自助统计接口发送渠道参数。
- 默认不选择渠道，含义为统计全部渠道。
- 支持单选、多选、全选和清空。
- 本功能不修改历史数据，不新增数据库表或字段。

## 前端设计

### 筛选状态

为 `DashboardFilters` 增加 `channel_ids?: number[]`。筛选弹窗打开时读取当前已应用值，点击应用后统一更新父级筛选状态，重置时恢复为全部渠道。

### 渠道选择器

- 放在现有筛选弹窗的“仅管理员”区域。
- 渠道列表使用现有管理员渠道 API 获取，选项显示 `渠道名称（#ID）`，值使用渠道 ID。
- 支持搜索、多选、全选和清空。
- 选中一个渠道时显示渠道名称；多个渠道时显示首个渠道名称和已选数量；未选择时显示“全部渠道”。
- 渠道列表请求失败时保留当前选择，展示加载失败状态，不自动清除筛选。

### 请求参数

`buildQueryParams` 将管理员选择序列化为逗号分隔的 `channel_ids`，例如 `145,146,147`。空数组与未定义均不发送该参数。

筛选应传递到：

- 管理员模型统计 `/api/data`
- 管理员流量统计 `/api/data/flow`

模型统计卡片、缓存命中率和各模型图表共用同一份过滤后数据，因此无需在图表层重复过滤。

## 后端设计

### 参数解析

控制器解析可选查询参数 `channel_ids`：

- 缺省或空字符串：全部渠道。
- 有值：仅接受逗号分隔的正整数，去重后传给模型层。
- 包含非法值、0 或负数：返回业务错误，不执行宽松降级，避免误展示全量数据。
- 设置合理数量上限，防止异常超长 `IN` 查询。

### 查询逻辑

扩展管理员统计方法：

- `GetAllQuotaDates(..., channelIDs []int)`
- `GetFlowQuotaData(..., channelIDs []int, ...)`

当 `channelIDs` 非空时追加：

```sql
WHERE channel_id IN (...)
```

`quota_data.channel_id` 已存在索引，无需数据库迁移。用户名和时间范围等既有筛选条件继续与渠道条件取交集。

普通用户 `/api/data/self` 与 `/api/data/flow/self` 不接受渠道筛选，避免扩大普通用户可见维度。

## 缓存命中率语义

渠道筛选后的缓存命中率继续沿用数据看板当前 Token 加权公式：

```text
cache_read_tokens /
(input_tokens + cache_read_tokens + cache_write_tokens)
```

该指标与使用日志逐请求平均值语义不同；本功能不改变既有公式，只改变参与汇总的渠道集合。

## 测试

### 后端

- 未传 `channel_ids` 时结果与现有行为一致。
- 单渠道追加正确过滤条件。
- 多渠道使用 `IN` 过滤，并与时间、用户名条件共同生效。
- 重复 ID 被去重。
- 非数字、0、负数及超量 ID 返回错误。
- 普通用户接口忽略/不使用管理员渠道筛选。

### 前端

- 普通用户看不到渠道选择器。
- 管理员可加载、搜索、单选和多选渠道。
- 应用、重新打开、清空及重置均保持正确状态。
- 单渠道和多渠道被正确序列化。
- 渠道变化会触发统计重新请求，并同步刷新所有模型指标及流量图。
- 渠道 API 失败时不会丢失已应用筛选。

## 兼容性与回滚

- 请求参数为可选，旧前端与旧调用方行为不变。
- 无数据库迁移，不影响现有 `quota_data`。
- 回滚仅需恢复前后端代码版本。
